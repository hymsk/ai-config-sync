# ai-config-sync

> Keep configuration files in sync across Linux servers through a dedicated Git repository.

A rule-driven agent that collects local changes to managed files every few seconds, pushes them to a shared config repository, and writes remote changes back to this host. On a merge conflict it **pauses only the local machine** (creating an empty `ERROR_MERGE_FLAG` under the running user's home), preserves the Git conflict state for manual resolution, and resumes automatically once the flag is removed and checks pass.

[中文](README.zh-cn.md) · [Specification](SPEC.md) · [Changelog](CHANGELOG.md)

- Pure rule-driven: no LLM, no external Python dependencies (Python >= 3.9, ships a minimal TOML parser).
- Never rebases, force-pushes, resets or cleans; conflicts always preserve the scene.
- File-truth model: every change decision is an immediate "host file hash <-> Git blob hash" comparison; the only local state is an append-only transaction journal.

## Two repositories

| Repository | Contents |
|---|---|
| `ai-config-sync` (this repo) | The agent, seed templates, systemd unit |
| Config repo (e.g. `ai-shared-config`) | `.sync-config/` (runtime config + include list) and `source/` (managed file mirror) |

Paths under `source/` map one-to-one to host absolute paths:

```text
host /root/.config/opencode/AGENTS.md
  <-> source/root/.config/opencode/AGENTS.md
```

After installation the runtime config lives in the config repo's `.sync-config/config.toml` and `sync.list`; seed templates in this repo are used only by `install new` and never fall back at runtime.

## Directory layout (fixed absolute paths; runs as root)

```text
/etc/ai-config-sync/bootstrap.toml   # generated by installer: repo_url / branch / worktree
/var/lib/ai-config-sync/repo         # local clone of the config repo (working tree, -p to override)
/var/lib/ai-config-sync/state/       # journal.jsonl / backups/ / sync.log / lock
$HOME/ERROR_MERGE_FLAG               # conflict pause flag (the only $HOME dependency)
```

The agent's own directories are hard-excluded; no include-list rule can ever sync the agent itself out.

## Installation

```bash
# New config repo: target repository must be empty; seeded from templates
ai-config-sync install new <repo-url> [-b <branch>] [-p <path>]
#   --force: seed on an orphan branch inside a non-empty repo (a pure new ref,
#            existing branches untouched; requires an explicit -b naming a
#            branch that does not exist)

# Attach: target repo must already have a branch and a parseable
# .sync-config/config.toml
ai-config-sync install attach <repo-url> [-b <branch>] [-p <path>]
```

- Git URLs only; URLs with embedded `user:pass@` are rejected. Authentication uses the local SSH key or credential helper.
- When `-b` is omitted the git default applies: attach reads back `origin/HEAD`; new follows the remote-advertised unborn HEAD or local `init.defaultBranch`. The result is pinned into bootstrap.
- An existing bootstrap or working tree is always refused; re-binding = clean up manually, then reinstall.

## First-round adoption

```bash
ai-config-sync once                # preview differences only (differs/host-only/repo-only/...)
ai-config-sync once --prefer local # host wins: capture and push (overwrites remote)
ai-config-sync once --prefer repo  # repo wins: back up, then write back to host
ai-config-sync once --prefer merge # three-way: files differing on both sides produce
                                   # add/add conflict markers (ours=repo theirs=host),
                                   # resolved file by file manually
```

`--prefer` only affects files that exist on both sides with different content; one-sided files converge in every mode.

## Running

```bash
ai-config-sync run        # daemon (one round every interval seconds)
ai-config-sync once       # single round
ai-config-sync doctor     # health check: bootstrap/remote/branch/worktree/journal/flag
```

systemd deployment: `deploy/ai-config-sync.service`.

## The single-round transaction (P0-P7)

```text
P0 preflight (lock/flag/worktree health)
P1 load effective config and expand include list (stable read: two hashes agree)
P2 classify host changes vs round-start HEAD (A)
P3 write changes into worktree source/... and commit (explicit paths only, offline)
P4 fetch + merge origin/<branch> (conflict -> set flag, preserve scene)
P5 push (non-FF -> fetch+merge retry <= 3)
P6 write back to host: pre-write recheck (only when host == A; mid-round edits
   are never overwritten), format validation, backup, atomic replace
P7 journal checkpointed (next round's A = current HEAD)
```

Crash recovery: the journal fsyncs each phase before acting; on restart the last transaction record drives recovery (captured -> P4, merged -> P5, pushed -> P6). A corrupt journal is never guessed at: the agent enters `paused-needs-doctor` and `doctor` helps re-baseline manually.

## Conflict handling

**Strict conflict definition**: a managed file modified on both sides (host and remote) is always treated as a conflict and handed to a human — even when the edited regions do not overlap and git could auto-merge line-wise. Line-level fusion can produce a mixed configuration neither side wanted, so it is never automatic. One-sided changes and changes to different files still converge automatically.

```bash
git -C /var/lib/ai-config-sync/repo ls-files -u     # list conflicted paths
# The worktree holds the full ours-side content; both sides stay available:
git -C /var/lib/ai-config-sync/repo show :2:source/<path>   # ours
git -C /var/lib/ai-config-sync/repo show :3:source/<path>   # theirs
# Pick a side per file (ours=host capture theirs=remote; reversed for adoption)
git -C /var/lib/ai-config-sync/repo checkout --theirs -- source/<path>
git -C /var/lib/ai-config-sync/repo add <path>      # or edit, then add
git -C /var/lib/ai-config-sync/repo commit --no-edit
rm ~/ERROR_MERGE_FLAG
```

Deleting the flag without resolving re-sets the flag. A conflict pauses only this machine; other servers keep syncing. The protection is a merge driver (`aics-conflict`) the agent re-asserts every round; manual `git merge` is covered as well.

## sync.list syntax

```gitignore
# nothing is managed by default; plain line=include, !=exclude, last rule wins
# absolute paths only; ** crosses directory segments; directory recursion /path/dir/**
/root/.codeagent/AGENTS.md
/root/.config/opencode/**
!/root/.config/opencode/*.tmp
```

## Configuration

`.sync-config/config.toml` in the config repo (effective on every machine):

```toml
interval = 5                  # local check interval, seconds
remote_check_interval = 5     # remote check interval when idle, seconds
max_backups_per_file = 20     # pre-write backups kept per file (0 = never prune)

[git]
name = "sync-bot"
email = "sync-bot@invalid"
```

## Uninstallation

```bash
systemctl disable --now ai-config-sync   # if deployed via unit
python3 -m pip uninstall ai-config-sync
```

Data directories are preserved by default; `bash deploy/uninstall.sh --purge-data` removes `/etc/ai-config-sync` and `/var/lib/ai-config-sync` after an explicit confirmation (note: the working tree may contain unpushed commits and `state/backups/` holds your file history — push or archive them first).

## Known limits

- File deletions do not propagate: missing on host but present in repo -> recreated next round; deleted remotely -> kept on host.
- Config files rewritten by their own application create sync feedback loops; do not include them.
- All machines share one include list and one config; no per-machine variance.
- Only regular files; symlinks are skipped with a warning.
- Credential files (tokens, private keys, API keys) are excluded by default and should not be included; the repository owner may explicitly authorize syncing them (a private repo is still not a credential vault — plaintext credentials enter Git history and are copied to every syncing host).
